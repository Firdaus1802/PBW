RINGKASAN EKSEKUTIF

Aplikasi DompetKu adalah perangkat lunak berbasis web dinamis yang dirancang untuk mengelola arus kas (cashflow) harian mahasiswa. Masalah klasik yang sering dihadapi mahasiswa adalah ketidakteraturan dalam mencatat pengeluaran harian, kesulitan mengetahui sisa saldo riil, serta pencatatan manual pada buku kas atau aplikasi catatan yang tidak memiliki struktur relasional.

Dengan menerapkan metodologi Software Development Life Cycle (SDLC) Waterfall, sistem ini menyediakan fitur manajemen transaksi kas (Pemasukan dan Pengeluaran), kategorisasi transaksi, ringkasan saldo otomatis, pemfilteran data, serta fitur cetak laporan keuangan periodik. Basis data dirancang dengan normalisasi hingga Third Normal Form (3NF) guna menjamin keutuhan dan integritas data (ACID compliant).

BAB I
PENDAHULUAN

1.1 Latar Belakang Masalah

Pengelolaan keuangan pribadi merupakan salah satu tantangan paling esensial yang dihadapi oleh kalangan mahasiswa selama menempuh masa studi di perguruan tinggi. Sebagian besar mahasiswa menerima alokasi dana secara periodik, baik berupa uang saku bulanan dari orang tua, beasiswa pendidikan, maupun upah pekerjaan paruh waktu (freelance). Di sisi lain, kebutuhan harian mahasiswa mencakup pos pengeluaran yang beragam dan dinamis, seperti biaya sewa kamar kos, konsumsi makan minum, fotokopi dan pembelian modul kuliah, transportasi, pulsa internet, hingga rekreasi sosial.

Dalam praktiknya, mayoritas mahasiswa masih melakukan pencatatan secara konvensional menggunakan buku saku fisik atau berkas catatan teks sederhana di ponsel pintar. Cara manual ini menimbulkan sejumlah permasalahan mendasar:

  1. Rentan Terhadap Kelalaian dan Hilangnya Catatan: Buku catatan fisik berisiko hilang, rusak, atau tertinggal, sementara catatan teks acak tidak memiliki perhitungan saldo otomatis.
  2. Ketiadaan Agregasi Data Real-Time: Mahasiswa kesulitan melihat secara cepat berapa total uang yang telah dibelanjakan untuk makanan, berapa sisa saldo kas yang aman hingga akhir bulan, dan pos mana yang paling boros.
  3. Struktur Data yang Tidak Terintegrasi: Tanpa adanya basis data relasional, pengelompokan transaksi berdasarkan kategori (misalnya Uang Saku, Makanan, Kos, Transportasi) tidak dapat dilakukan secara konsisten dan sistematis.

Oleh karena itu, proyek akhir ini membangun aplikasi web dinamis DompetKu berbasis PHP Native dan basis data MySQL dengan pendekatan rekayasa perangkat lunak terstruktur. Aplikasi ini dirancang seringkas mungkin dengan antarmuka bergaya iOS yang intuitif, bersih dari elemen visual berlebihan, sehingga sangat mudah dioperasikan dan dipresentasikan dalam uji coba teknis di laboratorium.

1.2 Identifikasi Masalah

Berdasarkan latar belakang tersebut, identifikasi permasalahan dalam proyek ini dirumuskan sebagai berikut:

  1. Bagaimana merancang struktur basis data relasional (MySQL) yang ternormalisasi hingga 3NF dengan relasi Primary Key dan Foreign Key guna mencatat kategori dan transaksi kas tanpa risiko inkonsistensi data?
  2. Bagaimana membangun aplikasi web dinamis dengan operasi CRUD (Create, Read, Update, Delete) lengkap untuk mengelola transaksi pemasukan dan pengeluaran secara real-time?
  3. Bagaimana menyajikan antarmuka pengguna bergaya modern (iOS Style) yang bersih, responsif, tidak memicu distraksi visual (*no AI slop*), serta memudahkan pengguna dalam menyaring dan mencetak laporan arus kas?
  4. Bagaimana memastikan sistem berjalan andal dan bebas galat melalui pengujian fungsionalitas Black-Box Testing?

1.3 Tujuan Proyek

Tujuan dari pengembangan aplikasi ini adalah:

  1. Menghasilkan basis data relasional db_kas_mahasiswa yang memenuhi kaidah normalisasi 3NF dan integritas referensial.
  2. Mengimplementasikan kode program PHP berbasis PDO (PHP Data Objects) dengan penanganan sanitasi masukan guna mencegah kerentanan SQL Injection dan XSS.
  3. Menyediakan fitur pencatatan transaksi kas, filter data berdasarkan jenis/kategori, pencarian cepat, kalkulasi otomatis sisa saldo, serta rekap cetak laporan.
  4. Mendokumentasikan seluruh tahapan pengembangan sistem dalam laporan resmi berstandar SDLC Waterfall.

1.4 Nilai Manfaat Aplikasi

Manfaat yang diberikan oleh aplikasi DompetKu terbagi menjadi:

  1. Bagi Mahasiswa (Pengguna): Membantu mengontrol pengeluaran harian, mencegah defisit anggaran sebelum akhir bulan, serta memberikan transparansi alokasi dana secara terukur.
  2. Bagi Orang Tua / Wali: Mempermudah penyediaan bukti pertanggungjawaban arus kas mahasiswa saat diperlukan melalui fitur cetak laporan transaksi berkala.
  3. Bagi Pembelajaran Akademik: Memenuhi seluruh kompetensi mata kuliah Pemrograman Berbasis Web mengenai integrasi PHP, SQL, normalisasi database, pemisahan berkas konfigurasi, dan implementasi CRUD.

2.2.2 Kebutuhan Non-Fungsional (Non-Functional Requirements)

  1. Keamanan Data: Menerapkan PDO Prepared Statements pada semua query SQL dinamis guna menangkal celah SQL Injection. Seluruh output disanitasi menggunakan htmlspecialchars() untuk mencegah serangan Cross-Site Scripting (XSS).
  2. Desain & Kemudahan Penggunaan (Usability): Antarmuka mengadopsi Apple iOS Human Interface Guidelines dengan sudut membulat (border-radius: 16-22px), warna lembut yang tidak bertabrakan, palet warna pastel, dan bebas dari animasi mencolok atau *AI slop*.
  3. Kecepatan Kinerja: Halaman web ringan, memiliki waktu muat (load time) di bawah 30ms pada server lokal, dan tidak memerlukan dependensi kompilasi eksternal.

2.3 Tahap Perancangan Sistem (System Design)

2.3.1 Normalisasi Basis Data (1NF, 2NF, 3NF)

Basis data db_kas_mahasiswa dirancang melalui proses normalisasi terstruktur:

  1. Bentuk Tidak Ternormalisasi (UNF): Catatan transaksi dicampur aduk dengan nama kategori, tanggal, dan data pengguna dalam satu baris tanpa batasan tipe data.
  2. First Normal Form (1NF): Setiap atribut bernilai atomik (tunggal), tidak terdapat perulangan kolom. Ditentukan Primary Key unik untuk setiap entitas: id_user, id_kategori, dan id_transaksi.
  3. Second Normal Form (2NF): Seluruh kolom non-kunci bergantung secara fungsional penuh (fully functionally dependent) terhadap Primary Key pada tabel masing-masing.
  4. Third Normal Form (3NF): Menghilangkan ketergantungan transitif. Kategori dipisahkan ke dalam tabel master tersendiri (kategori). Tabel transaksi hanya menyimpan kunci asing id_kategori sebagai Foreign Key. Apabila nama kategori atau ikon diubah, sistem hanya memperbarui satu baris pada tabel kategori tanpa merusak riwayat transaksi.

2.6 Rencana Pemeliharaan & Deployment

2.6.1 Panduan Menjalankan di Lingkungan Lokal (Localhost)

  1. Jalankan aplikasi Laragon atau XAMPP, pastikan modul Apache dan MySQL dalam status berjalan (Running).
  2. Buka basis data via phpMyAdmin atau HeidiSQL, lalu impor berkas skrip SQL: m6/database/db_kas_mahasiswa.sql.
  3. Arahkan browser ke alamat URL: http://localhost/m6 atau http://localhost/PBW/m6.

2.6.2 Rencana Deployment ke Server Cloud / Produksi

  1. Hosting & Domain: Menyiapkan shared hosting berbasis cPanel atau VPS dengan PHP versi 8.1 ke atas.
  2. Migrasi Database: Membuat database di server produksi dan mengimpor tabel melalui phpMyAdmin cPanel.
  3. Keamanan SSL: Mengaktifkan sertifikat HTTPS Let's Encrypt untuk mengenkripsi transmisi data di peramban.
